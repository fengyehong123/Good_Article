**STUN** 是 **Session Traversal Utilities for NAT**（NAT 会话穿越应用程序）的缩写。简单来说，它是一个网络协议，用来**帮助位于 NAT（网络地址转换）后面的设备发现自己对外的公网 IP 地址和端口**，从而实现点对点（P2P）通信。

### 为什么需要 STUN？
绝大多数家庭和企业设备都在路由器后面，使用的是私有 IP（如 192.168.x.x）。当你想和别人直接视频通话、联机游戏或传输文件时，对方无法直接连接你的私有 IP。路由器虽然做了 NAT，但通常只允许“内部先发起连接，外部才能回包”。STUN 就是为了解决“**我怎么知道自己在公网上的地址，并告诉对方**”这个问题。

### STUN 是怎么工作的？
1. 你的设备（客户端）向公网上的 **STUN 服务器**发送一个请求。
2. STUN 服务器收到请求后，会查看数据包的来源地址和端口，也就是你的设备经过 NAT 转换后，在公网上的地址。
3. 服务器把这个公网地址和端口写在响应里，发回给你的设备。
4. 你的设备就知道了：“哦，原来我在公网看来是 `203.0.113.5:54321`。”
5. 然后你就可以把这个地址告诉对方，尝试直接建立 P2P 连接。

### 常见用途
- **WebRTC**：浏览器里的视频通话、语音聊天，用它来发现双方的可达地址。
- **VoIP / 即时通讯**：如 SIP 电话、某些游戏语音。
- **P2P 文件传输 / 联机游戏**：帮助玩家之间直接连接，减少服务器中转。
- **NAT 类型检测**：判断你处于哪种 NAT 环境，是否容易打洞。

### 它不能做什么？
STUN **本身不负责中继流量**。如果双方都在严格的 NAT 后面（比如对称型 NAT），STUN 可能无法打洞成功。这时就需要 **TURN** 服务器来中转数据。所以通常的架构是：
- **STUN**：尝试直连（成本低、延迟低）
- **TURN**：直连失败时兜底中转（成本高、延迟高）

### 一句话总结
STUN 就是一个“**问公网我是谁**”的协议，用来帮助 NAT 后的设备发现自己的公网地址，从而让 P2P 通信成为可能。

### 🔍 为什么 STUN 会成为“内鬼”

禁用 STUN，其实是为了**防止你的真实 IP 地址在科学上网时被网站“看穿”**。
这背后涉及浏览器的一个内置功能：**WebRTC**。

WebRTC 是用来实现网页视频通话、文件直传的技术，它需要一个叫 **STUN** 的协议来帮设备发现自己的公网地址，以便建立点对点连接。

问题就出在这个“发现”的过程中：STUN 请求为了追求低延迟，可能会**绕过你的代理隧道**，直接通过你本地的网卡去询问 STUN 服务器：“我的公网 IP 是多少？”。

如果你挂着代理，普通网页流量都走了代理，但 STUN 请求却“私自”跑了出去。结果就是，网站通过网页里的脚本，拿到了你**真实的国内 IP 地址**，而不是你期望的代理 IP。这就等于你的伪装被“内鬼”出卖了。

### 🛡️ 后果是什么

一旦真实 IP 泄露，会带来两个很直接的麻烦：

1. **隐私和匿名性失效**：网站能直接看到你真实的运营商归属地，知道你人在国内，代理形同虚设。
2. **触发服务的地理限制**：比如 Google 可能因此判定你是国内用户，强制跳转到中文版或香港版页面，而不是你期望的英文或美国版。

### 💡 怎么“禁用 STUN”

教程里说的“禁用 STUN”，通常是指**关闭浏览器的 WebRTC 功能**，或者**阻止它使用非代理的 UDP 连接**。

不同浏览器的操作方式不同：

*   **Firefox**：最彻底。在地址栏输入 `about:config`，找到 `media.peerconnection.enabled`，把它改成 `false` 就行。
*   **Chrome / Edge**：浏览器本身没有直接开关，通常需要安装扩展，比如 **WebRTC Leak Shield** 或 **WebRTC Leak Prevent**，并在扩展设置里选择“Disable non-proxied UDP (force proxy)”来强制 WebRTC 流量走代理。

**需要注意**：禁用 WebRTC 后，网页版 Discord、Skype 或 Google Voice 的语音/视频通话功能可能也会失效。如果你不常用这些功能，为了隐私，关掉是更安全的选择。
